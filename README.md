## MetaTube 番号刮削

调用 NAS 上自建的 **MetaTube** 服务（`metatube-server` v1 API），按番号检索元数据，生成
`movie.nfo` + `poster.jpg` + `fanart.jpg` 并写入媒体目录。
**115 Cookie 直连模式无需安装或运行任何第三方网盘插件**，同时负责目录浏览、视频与字幕关联改名、
本地 STRM 与字幕生成，以及播放时获取 115 直链。仍在 MoviePilot 内运行，视频流量通过 302 跳转到 115。

### 115 独立模式快速配置（推荐）

1.1.1 起配置项随存储模式联动，无效开关自动隐藏。切换存储会重置临时浏览状态，保留已填参数；
路径不会自动转换，需重新确认扫描目录后保存。所有检查、浏览及执行操作使用已保存配置。
115 Cookie 检查状态显示在检查按钮旁，与刮削执行结果分别显示。运行中保存相同执行参数或仅调整调度不会打断任务；
修改凭据、扫描范围、输出位置等实际刮削参数，或停用/重载插件时会安全停止旧任务，保存后可重新执行续跑。

1. 存储类型选择 **115 Cookie 直连（独立生成 STRM）**。
2. 填写 **115 Cookie**（包含 `UID/CID/SEID`，有 `KID` 时一并保留）；
   此凭据与 **MetaTube Token** 不同。Cookie 仅由 MoviePilot 保存，不写入 STRM、NFO 或日志。
3. 填写 MetaTube 后端地址和 Token，以及 **MoviePilot 播放入口地址**，如 `https://mp.example.com`。
   该地址须能被 Emby/播放器访问；STRM 使用本插件的稳定入口，播放时重新获取临时直链。
4. **先保存配置**，再检查 Cookie，点击扫描目录旁的 **选择目录**，在弹窗中进入目标文件夹，
   点 **选择当前目录** 加入扫描范围，最后保存配置。可以重复选择多个目录；取消弹窗不改变扫描范围。
   扫描目录显示中文路径标签，后台按稳定 ID 定位；也可输入 `/jav`，或在弹窗输入 `id:123456` 后刷新。
   可删除标签；旧 ID 浏览后会补上名称，保存后保留名称缓存。支持扫描根目录中的散装视频。
5. 填写容器内可写的绝对路径作为 **本地 STRM 根目录**，首次使用独立测试目录，例如 `/media/metatube-test`。
6. 选择 **媒体库分类**（默认番号前缀，也可厂商归并）。开启 **网盘目录和文件按番号整理** 后，两端使用相同分类层级；可单选独立网盘目标目录，留空跟随当前扫描归档根。
7. 启用后先处理一部带字幕的影片。确认视频、字幕改名及本地产物正确，再扩大处理上限。

本地输出示例：

```text
/media/metatube-test/DSOD/DSOD-060/
  DSOD-060.strm
  DSOD-060.zh.ass
  DSOD-060 - V0001.strm
  movie.nfo
  poster.jpg
  fanart.jpg
```

**1.2.1 扫描与处理顺序：**按配置扫描根的顺序及 115 返回顺序逐目录读取，保留原有目录队列和扫描深度。
完整读完当前目录的分页后，按番号首次出现的顺序分组，逐部刮削、生成本地文件并整理网盘，再读取下一目录；不等待全库扫描。
当前目录内的同番号多版本、CD 分段和字幕一起处理。达到单次处理上限后立即停止读取后续目录；跳过已完成影片不占上限。
后面或下轮遇到同番号的新版本时继续追加，已有版本编号和播放链接保持不变；同番号每次任务只计一部，失败优先于未找到、成功和跳过。

**全量／增量扫描：**115 直连的“扫描模式”提供以下选择，默认全量；原有一级／递归选项改名为“扫描范围”。

| 扫描模式 | 本次从哪里开始 | 达到上限后 |
|---|---|---|
| 全量模式 | 每次从配置扫描根开始；仍跳过无变化的影片 | 下次从头扫描；执行全量会清除旧增量进度 |
| 增量模式 | 从数据库保存的未完成位置继续；首次使用从头开始 | 下次继续当前目录剩余影片，再扫描后续目录；重启后仍有效 |

增量扫完整个配置范围后，下次任务从头开启新一轮，不在同一次任务中循环；此前位置之前新增的文件留到新一轮发现。
例如当前目录有 100 部不同番号、上限 30，连续任务处理 30／30／30／10 部。
普通单片失败或未找到元数据会推进位置，下一轮重试；Cookie 失效、风控、主动停止、目录分页或进度保存失败保留未完成位置。
队列中的目录若已被删除或进入回收站（115 返回 800001），增量恢复时跳过该目录并记录 ERROR，继续扫描后续目录，不会每次都停在同一条错误上。
任务记录和日志显示模式、恢复位置、暂停原因和本轮完成状态。“强制更新”独立于扫描模式，不会因选择全量而自动开启。
变更账户、扫描根及顺序、扫描范围、输出根、网盘整理、媒体库分类、厂商规则、网盘目标或番号识别设置会重置位置；调整调度、单次上限、请求间隔或刷新同账户 Cookie 会保留位置。
检查点与媒体登记同存插件数据目录的 SQLite 中，按目录／文件 ID 恢复，不依赖整理前的路径或页码。

**云盘处理流程** 识别到完整元数据并成功暂存字幕、图片后，按文件 ID 在原目录改名视频与关联字幕，
多段视频保留 `-CD1/-CD2`，字幕保留语言及 `forced/default` 标记。
支持 `srt/ass/ssa/sub/idx/vtt/sup`，单个字幕上限 64 MiB；IDX 必须有配对 SUB。
每部影片的内部版本 ID 首次登记后固定；文件名的展示编号单独保存，多个版本分别生成 STRM，字幕跟随对应版本，共用一份 NFO 和图片。
配置父根 `/jav` 时，`/jav/IPX-201`、`/jav/IPX/IPX-201` 及父根内其他来源中的同番号，统一增量合并到 `/jav/IPX/IPX-201`。
重叠扫描范围和移动后再次遇到的文件按 ID 去重，已处理视频仍可关联后来新增的字幕。
未指定统一网盘目标时，真正独立的多个扫描父根不跨根合并；后发现同番号时提示选择共同上级目录，保留前面已完成的结果。指定统一目标后，多根同番号可合并为稳定的多个版本。
字幕或多套分段无法唯一关联时，ERROR 日志记录目录、原文件名及文件 ID。已改名文件和字幕关联记录在插件数据目录的 SQLite 中，
部分失败后按实际文件状态续跑；已有 NFO 不会阻止补齐缺失 STRM 或字幕。

**网盘目录和文件按番号整理** 115 直连模式可开启此开关，默认关闭。成功生成本地产物后，按所选分类／番号整理云盘；留空的目标配置随扫描根动态解析，不保存一份固定的扫描路径。

- 番号前缀布局使用 `/jav/IPX/IPX-939/` 和本地根目录下的 `IPX/IPX-939/`，原布局使用根目录下的 `IPX-939/`。`FC2-PPV` 和 `259LUXU` 使用完整前缀，纯数字番号归入“数字番号”。
- 视频和字幕按版本关联改名，例如 `IPX-939-CD1.mp4`、`IPX-939-CD1.zh.ass`；同番号的另一版本使用 `V0001`。分类层级不占用影片扫描深度，从分类目录开始扫描也会复用该分类。
- 逐目录根据当前网盘文件识别影片、分配版本并生成本地产物；处理进度持久保存，部分失败后可继续。

**1.4.1 首份纯番号命名：**没有名称占用时使用 `IPX-338.mp4`；基础名称已被占用时，新来的 AVI 使用 `IPX-338 - V0001.avi`，再重复则使用 `V0002`。不同视频扩展名共用编号空间，视频扩展名原样保留；同一文件 ID 重复扫描不会追加版本。
CD1/CD2 共用一个版本：首份使用 `IPX-338-CD1.mp4`、`IPX-338-CD2.mp4`，另一套使用 `IPX-338 - V0001-CD1.mp4`。STRM 与字幕跟随对应视频名称；NFO、图片保持共享。

升级后也会按单次影片上限调整已登记存量：原 `V0001 / V0002` 改为“纯番号 / V0001”；已有纯番号版本优先保留，外部文件占用的编号跳过。先读取最终网盘目录和本地目录的实际占用，未登记的视频／STRM 只占位、不接管；已被人工修改的受管文件报告冲突并保留。
展示编号与内部版本 ID 分开持久保存；此次迁移后，已登记编号保持稳定，新版本选择最小空闲编号，已有登记仍预留自己的槽位。保持媒体 ID 和 STRM 内容／播放链接不变，复用有效字幕与图片。

改名意图、临时名和执行阶段保存在原有 SQLite 迁移日志中；只有存在名称依赖时才为网盘文件使用临时名，本地通过暂存名防止覆盖。操作中断后核验实际文件 ID、摘要和位置，再从日志恢复。命名规则修订会重置旧目录游标，先处理登记库里的迁移任务，因此来源目录已空、影片位于扫描范围之外时仍能改名。
关闭网盘整理时，存量只迁移本地名称，云端待办保留；重新开启后继续。原有普通直连发布流程和存量迁移分别保留自己的恢复状态。停止、鉴权／风控和提交失败暂停并保留位置；普通单片冲突记录后继续。

**1.4.0 厂商归并及迁移：**仅 115 直连模式提供 `library_layout`（`prefix`／`maker`）、`maker_groups`、`archive_root` 和 `cleanup_empty_dirs`。旧配置仍按前缀归档。

厂商归并默认 S1、IDEA POCKET、MOODYZ、MADONNA、PREMIUM、ATTACKERS 六组，加上“其他厂商”“未知厂商”，共八类。
优先用元数据 `maker`，为空才用 `label`。非空但未匹配规则的归“其他厂商”，均为空归“未知厂商”；不会从番号猜测厂商。
规则每行 `目录名=别名1,别名2`，目录名自身也是别名；支持增删分组。经过全半角、大小写和空白规范化后精确匹配，重复别名／分组及不安全目录名会阻止执行。
预置英文、日文别名参考 [S1 官方名称](https://s1s1s1.com/) 与 [IDEAPOCKET 官方名称](https://ideapocket.com/)。例如：

```text
S1=S1 NO.1 STYLE,エスワン,エスワン ナンバーワンスタイル
IDEA POCKET=IDEAPOCKET,アイデアポケット
主力厂商=自定义厂商名称,別名
```

```text
网盘：{网盘整理目标根}/IDEA POCKET/IPX-201/视频和字幕
NAS： {本地媒体库根}/IDEA POCKET/IPX-201/STRM、字幕、movie.nfo、图片
```

开启整理后显示 **网盘整理目标目录**，可以手填绝对路径或 `id:目录ID`，也可点击“选择整理目录”单选。选择结果在同一控件中显示网盘路径，保存时保留目录 ID，取消不改变配置。
留空跟随各扫描归档根，本地根目录独立设置。目标位于扫描目录内部时，发现流程排除该目标子树；已登记影片通过文件 ID 定位，避免重新扫描整个目标。配置的扫描根始终保留，不整体移动或删除。

修改分类规则或目标后，先从登记库生成重分类／重定向任务，再补充正常目录扫描，均受单次影片上限约束。
因此原来源目录已空、影片已在扫描范围外，也能再次迁移。未完成迁移优先恢复，移动前写入 SQLite 日志，逐文件确认实际位置并更新登记。
本地只迁移归属本插件且摘要未改变的文件，保留已有版本号、字幕关联、媒体 ID、STRM 播放链接及有效图片；目标冲突保留原件，其他影片继续。
按文件记录来源；旧登记只能在来源父目录与扫描范围可核验时补齐，无法确认时报告并跳过。更换账户或移除来源后，相关任务冻结；关闭整理后不重放迁移的网盘操作。
规则／目标变化重置目录游标，但保留迁移日志和媒体登记，并根据当前配置重规划。遇到 115 明确标为永久删除的登记文件时，清理该文件的登记和播放标识，移除归属与摘要可核验的本地输出。

**媒体服务器刷新** 默认关闭。开启后可多选 MoviePilot 中已配置的服务器。任务生成、迁移或清理 STRM 后，每轮通知选中的服务器并记录结果。留空跳过刷新。

**迁移后清理旧空目录** 默认开启：只清理本次迁空的旧影片／旧分类目录，保留扫描根、整理根、非空目录和其他祖先目录。
本地只调用空目录删除；网盘在再次核对 ID、父子关系、名称和空状态后移入回收站，不清空回收站。删除响应不确定时保留日志，下次按 ID 核验。
115 接口没有空目录原子删除保护，自动网盘清理要求同目录没有其他写入任务；有下载器、其他插件或人工同时写入时请关闭此开关。

**本地文件保护：**只更新本插件记录中归属当前影片、且内容未被人工修改的文件。已有其他工具生成的同名文件会报告冲突，
不会自动接管或删除；已有 STRM 保持原样。更换账户时旧播放标识不可用于新账户。

**请求与播放：**后台请求默认间隔 5 秒并串行执行，这不是保证不触发风控的安全阈值。
遇到 Cookie 失效、验证码或频控会停止任务。视频只提供 302 直连，不能直连时明确报错，不经 NAS 转发视频。
停止定时刮削不影响已生成 STRM 的播放；播放需要 MoviePilot 和本插件持续运行。

**依赖：**直连模式要求 Python 3.12+，插件锁定 `p115client==0.0.9.6.5.1` 与 `python-concurrenttools==0.1.8`。
低版本 Python 跳过这些依赖，仍可使用本地存储模式。插件不共享可变 Cookie 文件，也不会自动反复扫码登录。

媒体服务器应读取本地 NFO 和图片，避免向同目录回写 NFO；回写会改变插件已登记的文件内容，
下次执行将按文件保护规则报告冲突，而不会覆盖该文件。

新安装默认直连模式；已有配置保留原模式，需主动切换并填写上述配置。以下涉及 StorageChain、网盘写入和
自动归位的说明适用于非直连模式，直连模式不依赖这些功能。

### 功能特性

- 按番号调用 MetaTube 检索，支持多数据源按序 fallback（FANZA、JavBus、MGS 等，以 `/v1/providers` 返回为准）
- 生成 Kodi 标准格式 `movie.nfo`，供 Emby/Jellyfin 读取本地元数据；标题以番号开头，简介保留源站原文并补充已有影片资料
- **可视化目录选择**：先选存储（本地 / u115 等），再逐级浏览选择媒体目录，避免手输错误
- 灵活的输出位置：写入本地 STRM 目录（推荐）或网盘目录，支持自动归位（资源库 → 媒体库）
- 内置防风控：文件写入间隔、单次处理上限、增量跳过、任务运行互斥
- 表单内置「测试数据源 / 立即执行」按钮，插件详情页展示上次运行统计

### 一、适配的服务端

官方镜像 `ghcr.io/metatube-community/metatube-server:latest`，使用 v1 API：

| 接口 | 用途 |
|---|---|
| `GET /v1/movies/search?q={番号}&provider={源}&fallback=true` | 按番号检索 |
| `GET /v1/movies/{provider}/{id}` | 获取完整元数据 |
| `GET /v1/images/primary/{provider}/{id}` | 海报（服务端代理，规避源站防盗链） |
| `GET /v1/images/backdrop/{provider}/{id}` | 背景图（同上） |

服务地址填 MoviePilot 容器视角可达的地址（例如 `http://192.168.1.60:8090`）。
若 MoviePilot 也是 Docker 容器且非 host 网络，不要填 `127.0.0.1`。

### 二、安装

1. MoviePilot 网页端 → 插件 → 插件市场 → 添加仓库：

   ```
   https://github.com/zcs19960929/MoviePilot-Plugins
   ```

2. 刷新插件市场，搜索「MetaTube 番号刮削」安装并启用。

> 备选：直接把 `metatubescraper` 文件夹拷进 MoviePilot 容器的插件目录并重启。

### 三、配置说明

| 配置 | 默认 | 说明 |
|---|---|---|
| MetaTube 服务地址 | - | 如 `http://192.168.1.60:8090` |
| Token | 空 | 服务端启用鉴权时填写相同的原始 Token，**无需添加 `Bearer` 前缀**；未启用时留空。修改后先保存再测试 |
| 数据源优先级 | FANZA,JavBus,MGS,... | 逗号分隔按序尝试；**ID 必须与 `/v1/providers` 返回一致（区分大小写）**。可用性以数据源自检为准；FC2 专用源仅适用于 FC2 番号 |
| **存储类型** | 115_direct | `115_direct` Cookie 直连；兼容 `local` 本地存储 / `u115` / 其他存储名 |
| 115 Cookie | 空 | 直连凭据；保存后再检查与浏览目录 |
| MoviePilot 播放入口地址 | 空 | 直连模式必填，Emby/播放器可访问的 MoviePilot 地址 |
| 115 后台请求间隔 | 5 秒 | 仅直连模式生效；与旧模式的文件写入间隔分别配置 |
| **扫描目录** | - | 点击“选择目录”在弹窗中添加，可选多个；直连显示路径标签，本地或兼容模式每行一个路径，也可手填 |

| 扫描范围 | 一级子目录 | 保留原配置键 `scan_mode`；直连包含根目录散装视频，分类目录不占影片深度 |
| 文件写入间隔 | 3 秒 | **每个文件写入前等待，防风控核心参数** |
| 单次处理上限 | 30 部 | 分多次执行，避免单次大批量写盘 |
| 调度方式 | 每天 04:30 | 支持仅手动、每天、每周、间隔分钟、自定义五段 Cron；按宿主时区执行 |
| 强制更新 | 关 | 直连模式关闭时仍补齐缺失文件，开启时也只更新归属插件且未被修改的文件；兼容模式关闭时跳过已有 NFO 的影片 |

直连模式始终输出本地媒体库，不使用兼容模式的网盘写入或自动归位开关。
本地存储模式在影片原目录输出；其他网盘模式需至少选择一种有效输出，写入本地时需同时填写两端媒体库根目录。
兼容模式改名不关联外挂字幕，请谨慎开启。

### 四、兼容模式的 115 写入注意事项

1. **只增不删不改**：插件默认只新增 `movie.nfo / poster.jpg / fanart.jpg`，不移动、不删除、不重命名
   （重命名功能默认关闭）。挂载盘写小文件总体风险较低，但仍需克制频率。
2. **写入间隔 ≥ 3 秒**：不要为了快把间隔调小；首次全量刮削量大时，靠「单次上限」分几天跑完。
3. **优先用一级子目录模式**：避免递归遍历大量目录触发频繁的列目录请求。
4. **夜间定时 + 增量跳过**：重复执行不会重复写盘，已处理的目录直接跳过。
5. **不要频繁手动触发**：任务运行中重复点击无效（内置互斥锁）。
6. 若遇 115 风控（写入报错/挂载卡死），立即停止任务，暂停 24 小时后再以更大间隔小批量处理。

### 五、调度与媒体服务器配合

**1.1.2 调度：**在“调度方式”选择仅手动、每天、每周、每隔 N 分钟或自定义 Cron，页面只显示相关字段。
已有配置继续每天按原小时/分钟执行，支持 `00:00`；切换方式保留其他字段值。
间隔为 `1–525600` 的整数分钟，从任务注册时开始计时，配置重载后重新计时。全部使用 MoviePilot 宿主时区。
“仅手动”关闭自动扫描，已有 STRM 播放仍可使用。

Cron 使用宿主 APScheduler 3 的五段格式 `分 时 日 月 星期`，不含秒：

| 表达式 | 含义 |
|---|---|
| `30 4 * * *` | 每天 04:30 |
| `*/30 * * * *` | 每小时的 00、30 分 |
| `0 */6 * * *` | 每天 00、06、12、18 点 |
| `0 4 * * mon` | 每周一 04:00 |
| `0 4 * * mon-fri` | 周一至周五 04:00 |

星期数字为 **0=周一、6=周日**，建议使用 `mon–sun`，与部分 Linux Cron 的星期编号不同。
保存后服务器校验；无效配置不注册定时任务，插件详情页显示原因，仍可手动刮削。

**NFO 与 Jellyfin：**标题采用 `SNOS-377 影片名称`，源站原标题保留在 `originaltitle`。
简介前补充番号、完整上映日期及已提供的片长、导演、厂商、发行商、系列、评分，随后保留原简介。
标准日期、年份、演员、分类和评分字段仍写入 NFO；源站缺失的信息不编造。

Jellyfin 支持读取 `movie.nfo`，电影详情页的年份位置通常只显示年份，因此完整日期通过简介展示。
该媒体库建议关闭在线元数据/图片下载器，自动在线刷新设为“从不”；已有本地 NFO 和 poster/fanart 可直接读取。
**“元数据储存方式 → Nfo”控制回写，应关闭，不影响读取。** 同目录交由本插件生成元数据时，也关闭“将媒体图像保存到媒体所在文件夹”。
STRM 媒体库可关闭进度条预览图、章节图片提取，减少远程视频读取。

升级后正常扫描已完成的直连影片时，插件会用登记的缓存资料更新归属插件且未被修改的 NFO，
保持 STRM 播放标识，不重新下载已有图片/字幕或重复改名；同次扫描仍会正常处理新影片。
兼容模式按原有强制更新规则处理已有 NFO。更新文件后在 Jellyfin 刷新该片本地元数据；若仍显示旧标题，
确认该片标题未被手动锁定，且在线下载器已关闭，再刷新元数据。无需重新生成 STRM。

本地元数据完整时，Jellyfin 的 MetaTube 刮削器可以在该媒体库停用；播放仍需要 MoviePilot、本插件及有效 115 Cookie。

### 六、手动触发与 API

- 插件配置表单内置「立即执行」按钮；插件详情页可查看上次运行统计（成功/跳过/未识别/未找到/失败）；
- API 手动触发：`GET /api/v1/plugin/metatubescraper/run`（需 MP 登录凭证或 API_KEY）；
- 数据源自检：`GET /api/v1/plugin/metatubescraper/selftest?q=SSIS-110`，
  用指定番号逐个测试已配置的数据源，区分「provider 不存在 / 搜不到 / 有结果」，排障利器。

**测试前先保存配置**：测试按钮使用服务端已保存的 MetaTube 地址、Token 和数据源，
不会读取表单中尚未保存的修改。自检与正式刮削均通过 `Authorization: Bearer <Token>` 鉴权。
`/v1/providers` 可公开访问，返回 200 不能证明 Token 有效；应使用搜索接口验证。

### 七、存储与目录选择

### 交互方式

1. **存储类型**：选择 `115 Cookie 直连` / `本地存储（local）` / `MP 原生 115（u115）`，
   也可直接手填其他已配置存储名；
2. 点击扫描目录旁的 **选择目录**，弹窗自动加载目录；点击文件夹进入，点击 **上一级** 返回；
3. 到达目标后点 **选择当前目录**，加入扫描目录；可重复添加多个目录，取消或关闭不会添加；
4. 也可在弹窗的当前路径框输入路径后点击 **刷新**，读取成功后再确认。空文件夹也可选；
5. 主页面的 **扫描目录** 才是任务使用的范围，确认后请保存；浏览其他位置不会自动改变它。

115 Cookie 直连使用本插件的独立浏览接口，无需安装任何第三方网盘插件；显示中文路径，保存稳定目录 ID。
其他模式通过 MoviePilot 存储接口浏览，需先配置对应存储。浏览均使用已保存配置，修改凭据或存储后先保存。

### ⚠️ 各存储的能力差异（务必了解）

| 存储 | 目录浏览 | 上传（写 NFO/海报） | 说明 |
|---|---|---|---|
| `local` | ✅ | ✅ | 文件系统直写，适用于 rclone / CloudDrive2 挂载路径 |
| `u115`（MP 原生） | ✅ | ✅ | 走 115 开放平台 OSS 分片上传，需先在「存储&目录」完成 115 授权 |

因此推荐两种落地方案：

- **方案 A（推荐，改动最小）**：NAS 上装 rclone 或 CloudDrive2，把 115 挂载成目录并映射进 MP 容器，
  插件存储类型选 `local`，目录用浏览器选到该挂载路径。写入走文件系统，速度最快。
- **方案 B**：在 MP「存储&目录」中添加原生 `115` 存储并完成扫码授权，插件存储类型选 `u115`，
  目录填 `/jav`。写入走 StorageChain 上传，受 115 API 限速约束，务必保持写入间隔 ≥ 5 秒。


### 八、本地 STRM 目录映射与归位

面向「插件生成 STRM + Emby 读 NFO + 爆米花直连 Emby」的架构，适用于非直连的网盘存储。

### 新增配置

| 配置 | 说明 |
|---|---|
| 写入本地 STRM 目录 | 默认开。NFO/海报写到本地，与本片 `.strm` 同级，零网盘写入风险 |
| 写入网盘目录 | 默认关。需要存储支持上传（u115 / alist） |
| 网盘媒体库根目录 | 如 `/jav`，即 115 上媒体库的根 |
| 本地 STRM 根目录 | 如 `/media/strm/jav`，与网盘媒体库根目录对应的容器内路径 |
| 自动归位 | 默认关。把番号影片移动到 `媒体库根目录/{番号}`；需要存储实现 `move` |

路径映射规则：网盘 `/jav/SSIS-110` → 本地 `{STRM根}/SSIS-110`。

### 两种落地姿势

**姿势一：u115 存储 + 手工归位**

1. 把番号影片从资源库移动到 115 的 `/jav/{番号}/`（手工或现有流程）；
2. 插件存储类型选 `u115`，媒体目录 `/jav`，`写本地 STRM 目录=开`、`写网盘=关`；
3. Emby 库指向本地 STRM 目录，元数据读取器勾选 NFO；爆米花直连 Emby。

→ 元数据写到本地，网盘只读不写，不需要 115 开放平台授权以外的任何操作。

**姿势二：u115 存储 + 自动归位（全自动）**

1. MP「存储&目录」添加原生 115 存储并扫码授权，记下存储名；
2. 插件存储类型填该名，媒体目录填资源库路径（如 `/待整理`）；
3. 开启「自动归位」，媒体库根目录 `/jav`，本地 STRM 根目录填好；
4. 优先级：先跑 1 部验证 move 与 NFO 落盘，再放大单次上限。

> 自动归位需要存储实现 `move`；不支持时插件会记录失败日志，此时请改用姿势一。
>
> 以上两种姿势都依赖 MoviePilot 的 StorageChain。若想完全绕开存储授权、由插件自己直连 115 生成 STRM，
> 直接用默认的 **115 Cookie 直连** 模式即可，见上文「115 独立模式快速配置」。

**常见问题定位**

| 现象 | 排查 |
|---|---|
| 直连模式无法加载 SDK | 检查 MoviePilot Python 是否为 3.12+，以及两项固定版本依赖是否安装成功；不要单独升级这组依赖 |
| 直连生成失败但已有 NFO | 查看上次运行错误，检查本地同名文件归属、字幕下载和命名冲突；直连模式不会因 NFO 存在就跳过缺失产物 |
| STRM 播放返回 404/503 | 检查是否使用本插件生成的播放标识、是否更换 115 账户、Cookie 是否失效，以及播放器能否访问配置的 MoviePilot 地址 |
| 测试数据源全部返回 401 | 更新插件至 v1.0.1 或更高版本（修复自检漏传 Token）；填写与服务端一致的原始 Token，先保存再测试。若仍为 401，检查服务端实际启用的 Token。404/500 是后续检索错误，应按数据源返回详情排查 |
| 统计里「未识别」多 | 开「识别无字母番号」试试；注意噪音词（H265/10bit 等）已内置过滤 |
| 「未检索到」多 | 先 `GET /v1/providers` 确认数据源存在，**provider ID 区分大小写**（如 `JavBus`/`FANZA`/`MGS`，官方镜像没有 javdb/javlibrary/avmoo，填错报 404 provider not found）；或直接调插件 `/selftest` API 逐源探测；看 metatube 容器日志（源站需代理） |
| NFO 写入失败/卡住 | 115 挂载写权限、uid/gid 映射；风控时会有明显延迟或报错 |
| 海报下载失败 | 检查 `/v1/images/primary/...` 是否能通；MetaTube 版本过旧可能无该代理接口 |
| FANZA 返回 `not-available-in-your-region` | **代理出口 IP 不在日本**（DMM 区域限制）。注意：`fallback=true` 命中 DB 缓存时会误以为可用，需用库里没有的番号才能测出。给 metatube 换日本节点代理，`curl https://ipinfo.io/country` 验证 |
| JAV321 报 `certificate is not valid for any names` | 代理做了 TLS 中间人，Go 客户端拒绝。关闭该域名的 TLS 解密/嗅探，或直连 |
| MGS 返回 403 | Cloudflare 拦截数据中心 IP。换住宅节点，或忽略该源 |
| DUGA 返回 503 | 站点自身不可用/限流。换源，无需处理 |
| 插件列表里找不到 | 确认目录名 `metatubescraper` 与类名 `MetaTubeScraper` 大小写对应、package.json 键名为 `MetaTubeScraper` |
| 配置保存后任务时间没变 | `get_service` 的 cron 只在插件启用/配置变更后重新注册 |
